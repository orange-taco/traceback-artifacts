먼저 전체 경로

일반적으로 이 다섯 경계가 필요합니다

화살표는 데이터 또는 작업이 다음 주체로 넘어간다는 뜻입니다. 공개 읽기와 비공개 쓰기를 같은 페이지에서 제공하더라도, 권한 판단은 서버가 해야 합니다.

Public · host① 누구나 문서 읽기

정적 HTML은 로그인 없이 열린다. 링크에 문서 URL과 게시 revision을 실어 보낸다.

Auth · server② 작성자 확인

서버가 GitHub 계정 ID와 세션·CSRF를 검사한다. 방문자에게는 저장 권한이 없다.

Private · storage③ 의견만 보관

문서 위치, 의견, revision을 비공개 파일로 기록한다. 원본 HTML은 바뀌지 않는다.

Manual · agent④ 수정 여부 결정

소유자가 Codex Cloud 작업을 따로 시작해 의견 파일을 읽고 수정 방향을 정한다.

Review · publish⑤ PR 검토 뒤 게시

문서 변경 PR을 검토하고 병합하면 공개 Pages가 새 HTML을 배포한다.

TRACEBACK 대응: GitHub Pages → Cloudflare Worker → oscar2272/traceback-feedback → 개인 Codex Cloud 환경 → orange-taco/traceback-artifacts PR과 Pages. 의견 저장은 Codex 실행 요청이 아닙니다.

방문자 경로

Pages의 HTML은 읽을 수 있습니다. Worker는 로그인하지 않은 저장 요청에 HTTP 401을 반환합니다.

소유자 경로

GitHub ID 88140361로 로그인한 세션만 저장할 수 있습니다. 다른 ID는 로그인 콜백에서 HTTP 403을 받습니다.

도구를 고른 이유

각 층의 선택은 서로 독립적입니다

한 도구가 공개 문서, 계정 인증, 비공개 저장, Codex 실행을 모두 대신하지 않습니다. 아래 선택을 바꾸면 어느 경계가 달라지는지 먼저 봅니다.

공개 문서 · GitHub Pages

이미 쓰는 URL과 PR 검토를 유지

정적 문서 배포는 Pages가 맡습니다. HTML 변경 PR에서 CodeRabbit 검토를 받을 수 있고, iPad에는 로컬 clone이 필요하지 않습니다.

대안: 전체 웹앱 서버는 한 곳에서 UI와 API를 제공하지만 호스팅·운영 부담이 커집니다. Pages만으로는 소유자 전용 비공개 저장 API를 만들 수 없습니다.

의견 저장 · 비공개 GitHub 저장소

파일이 곧 Codex의 입력

의견마다 JSON 파일 하나를 커밋합니다. Codex Cloud가 같은 저장소를 checkout하면 DB 조회용 MCP 없이 파일을 읽습니다.

대안: 공개 저장소의 Issues는 의견 비공개 조건에 맞지 않습니다. 비공개 저장소 Issues도 가능하지만 Codex가 파일처럼 바로 읽으려면 별도 조회 단계가 필요합니다. 별도 DB는 검색·확장에 유리하지만 서비스와 연결을 더 운영해야 합니다.

인증·쓰기 · GitHub App + Worker

권한 검사는 브라우저 밖에서

GitHub OAuth는 사용자 신원 확인, App 설치 토큰은 비공개 저장소 쓰기에 사용합니다. 키는 Worker 비밀값에만 둡니다.

대안: 브라우저에 PAT나 OpenAI API 키를 넣으면 공개 JS를 읽는 누구나 키를 가져갈 수 있습니다. 서버 없는 개인 프롬프트 생성은 의견을 저장하지 못합니다.

수정 · 수동 Codex Cloud 작업

저장과 수정은 별도 결정

의견 파일이 생겨도 작업은 시작되지 않습니다. 소유자가 의견 ID를 지정해 Codex에 읽기 또는 수정 요청을 따로 보냅니다.

대안: 자동 실행 파이프라인은 편하지만 별도 실행 API, 권한 경계와 비용을 설계해야 합니다. 이 구성은 지원되지 않는 Codex 자동 실행을 주장하지 않습니다.

추가 요금 경계 · 2026-10-08: 공개 Pages와 개인 비공개 저장소는 GitHub Free의 Pages·저장소 지원 범위, Worker는 Cloudflare 무료 요청 한도 안에서 사용합니다. Codex Cloud는 기존 ChatGPT Plus 사용량을 쓰며, 이 구성은 OpenAI API를 호출하지 않습니다. 각 서비스의 한도와 남은 Codex 사용량은 다시 설정할 때 확인하세요.

05 · Worker secrets

키는 Worker에만 등록

왜 secret인가? Pages HTML, feedback.js, PR diff, 브라우저 저장소에는 GitHub 토큰이나 OpenAI API 키가 없어야 합니다.

08 · Live verification

  const owner = await session(request, env);
  if (!owner) return new Response("Unauthorized", { status: 401 });

  let fields;
  try { fields = await limitedFormData(request); } catch { return new Response("Invalid form", { status: 400 }); }

문제가 생기면

멈춘 지점에서 되돌아가기

Pages에 의견 버튼이 없다

FEEDBACK_WORKER_ORIGIN 변수, Pages workflow 성공, 공개 site-config.json의 revision과 origin을 순서대로 확인합니다. HTML은 계속 읽을 수 있습니다.

GitHub 로그인 뒤 양식이 안 열린다

GitHub App callback이 Worker origin의 /oauth/callback과 정확히 같은지, client secret이 Worker secret에 있는지 확인합니다. 브라우저 URL에 secret을 넣지 않습니다.

의견 저장에 실패한다

App 설치 대상이 개인 비공개 저장소 한 곳인지, private key와 설치 ID가 Worker secret에 있는지 확인합니다. Worker 오류를 보고 GitHub 토큰 발급 실패와 파일 쓰기 실패를 구분합니다.

Codex에서 의견 파일이 403이다

ChatGPT Codex Connector를 개인 계정에도 설치했는지, 의견 저장소가 선택됐는지, 환경에 네 번째 저장소를 추가·재게시했는지 확인합니다. 새 작업으로 다시 읽습니다.
