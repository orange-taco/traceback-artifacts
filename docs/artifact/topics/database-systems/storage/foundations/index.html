테이블 이름을 알면
데이터 파일도 찾을 수 있을까?

SQL에서 보이는 users 테이블, 운영체제에서 보이는 파일, 그 파일 안의 Page와 Row는 같은 대상을 서로 다른 층에서 본 모습입니다. 이름과 파일이 항상 하나씩 짝을 이루지는 않습니다.

그림의 범위 · 가상의 shop.public.users와 id=7을 계속 사용합니다. 특정 TRACEBACK 서버의 실제 파일이나 설정을 뜻하지 않습니다. PostgreSQL 용어로 먼저 읽고, DBMS마다 다른 구현은 마지막 심화 자료에서 비교합니다.

읽는 방향 · SQL 이름에서 파일로, 파일에서 Page로 내려갑니다. 역방향으로는 Page와 파일만 보고 원래 SQL 이름을 단순히 추측할 수 없습니다.

먼저 기억할 정의

DBMS는 데이터를 저장하고 SQL 요청에 답하는 소프트웨어입니다. 이 소프트웨어가 논리 이름과 저장 파일의 관계를 관리합니다.

가장 흔한 착각

public.users라는 이름의 OS 폴더·파일이 반드시 생기는 것은 아닙니다. 파일 하나가 Row 하나인 것도 아닙니다.

Layer 01 / SQL에서 보는 구조

논리 객체는 “무엇을 다루는가”를 정합니다

Database: shop ├── Schema: public ← 이름 공간 │ ├── Table: users ← Row의 집합 │ └── Index: users_pkey ← 찾기 위한 별도 객체 └── Schema: analytics └── Table: users ← 같은 이름도 공존
폴더 비유의 한계 · Schema는 이름 충돌을 막는 논리적 구획입니다. public/와 analytics/라는 OS 디렉터리를 자동으로 만든다는 뜻은 아닙니다.

이 층의 단어

  • Database: PostgreSQL 인스턴스 안의 독립된 데이터베이스.
  • Schema: 그 안에서 객체 이름을 구분하는 네임스페이스.
  • Table: 컬럼 규칙에 따라 Row를 다루는 객체.
  • Index: 특정 값으로 Row를 빨리 찾도록 돕는 객체.

Relation은?

PostgreSQL에서 Table과 Index 모두 Relation으로 관리됩니다. Relation은 이 층과 저장 층을 이어 주지만, “Relation = OS 파일 하나”는 아닙니다. 정확한 연결은 심화 자료에서 봅니다.

Layer 02 / 운영체제가 보는 구조

물리 저장은 “바이트가 어디에 놓이는가”입니다

SSD / HDD 또는 클라우드 블록 장치→ OS가 사용파일시스템
파일시스템이 디렉터리와 파일 경로를 제공
PGDATA/ ← PostgreSQL 데이터 디렉터리 └── base/ └── 16384/ ← Database OID 예시 ├── 24576 ← users Main Fork 예시 └── 24577 ← users_pkey 예시
경계 · 위 트리는 PostgreSQL 기본 tablespace의 OS 디렉터리·파일 예시입니다. 16384와 24576은 설명용 숫자이며 실제 서버마다 다릅니다.

이 층의 단어

  • 저장 장치: 바이트가 남는 실제 매체 또는 서버에 연결된 블록 장치.
  • 파일시스템: OS가 디렉터리·파일 경로를 제공하는 방식.
  • 데이터 디렉터리: DBMS가 자신의 파일들을 두는 기본 위치.
  • 파일: OS가 경로와 바이트로 다루는 저장 단위.

DBMS와 OS가 맡는 일

OS는 파일 경로와 바이트 읽기·쓰기를 제공합니다. DBMS는 어떤 논리 객체의 데이터를 어느 파일에 두고, 그 바이트를 어떻게 해석할지 정합니다. 쓰기 시점에는 메모리 버퍼와 로그도 관여하므로 SQL 한 번이 곧 파일 한 번의 직접 쓰기라는 뜻은 아닙니다.

Page는 저장 블록, 자료구조는 배치 규칙입니다

상자 그림의 뜻 · Heap이 파일 안의 별도 폴더라는 뜻이 아닙니다. 파일을 Page들로 나눠 Row를 배치하는 조직 방식입니다. Page 0이 Page 1의 부모인 트리도 아닙니다.

이 층의 단어

  • Page: DBMS가 파일 안에서 다루는 저장 블록. PostgreSQL 기본 빌드는 보통 8KB입니다.
  • Tuple/Record: 컬럼 값과 관리 정보를 담는 Row의 저장 표현.
  • 자료구조: Page와 항목을 배열처럼 둘지, 탐색 트리로 이을지 정하는 방식.

Heap과 B-tree

PostgreSQL 테이블 본체는 Heap Page들에 Tuple을 둡니다. B-tree 인덱스는 키를 따라 Root·Internal·Leaf Page를 탐색합니다. 작은 트리에서는 Root 자체가 Leaf일 수 있습니다. Page는 OS나 SSD의 최소 저장 단위를 뜻하지 않습니다.
