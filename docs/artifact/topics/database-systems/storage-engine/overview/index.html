먼저 Database Engine이라는 넓은 용어와 실제 제품 형태를 구분합니다. 그다음 같은 UPDATE가 SQL 처리 계층을 지나 저장 계층에 닿는 과정을 따라갑니다.

페이지 전체에서 사용할 하나의 예제
UPDATE accounts
SET balance = balance - 100
WHERE id = 7;

뜻: accounts 테이블에서 id가 7인 한 기록을 찾아 balance를 100 줄입니다.

학습 범위 · 특정 TRACEBACK 배포 상태가 아닌 일반 개념입니다. 먼저 넓은 Database Engine 용어와 실제 형태를 구분하고, 이어서 서버형 관계형 DBMS에서 SQL이 저장 요청으로 바뀌는 과정을 봅니다. 제품별 자료구조와 저장 방식은 별도 엔진 학습 페이지에서 다룹니다.

정의

Database Engine은 데이터 연산을 수행하는 핵심 소프트웨어를 넓게 부르는 말이며, 모든 제품에서 같은 기능 범위를 뜻하지는 않습니다. 어떤 제품은 저장 기능만 Engine이라고 부르고, 어떤 제품은 SQL 처리부터 저장까지 묶어 Database Engine이라고 부릅니다. 따라서 이름만 보지 말고 어느 논리 계층까지 구현하는지 확인해야 합니다. 이 페이지에서는 데이터를 배치하고 찾고 변경하며 영속화하는 책임을 정확히 가리킬 때 Storage Engine 또는 저장 계층이라고 부릅니다.

기능 분류와 실행·제공 형태는 서로 다른 기준입니다. MySQL과 SQLite는 데이터베이스 관리 기능을 제공하는 DBMS이고, RocksDB는 저장 기능을 제공하는 Storage Engine입니다. 반면 Server는 별도 프로세스로 요청을 받는 실행 형태, Library는 호출자가 불러 쓰는 제공 형태이며, Framework는 애플리케이션의 구조와 제어 흐름을 제공하는 개발 도구 범주입니다.

따라서 MySQL은 서버형 DBMS, SQLite는 애플리케이션에 Library로 내장되는 DBMS, RocksDB는 Library로 제공되는 Storage Engine입니다. MySQL Server와 InnoDB는 Handler API를 경계로 논리적 책임을 나누지만, 일반적인 MySQL 구성에서는 별도 서비스가 아니라 같은 mysqld 서버 프로세스 안에서 동작합니다.

개념적 위치 지도요청을 받는 계층과 실제 저장 자원을 한 장에 표시

MySQL·PostgreSQL 같은 디스크 기반 서버형 관계형 DBMS를 단순화한 그림입니다. SQLite와 RocksDB를 이 시스템 안에 함께 넣은 구조가 아닙니다. SQLite는 애플리케이션에 내장된 전체 SQL DBMS이고, RocksDB는 SQL 처리 계층이 없는 Key–Value 라이브러리이므로 첫 번째 단계와 호출 주체가 다릅니다.

DBMS 내부 관련 기능: Buffer, WAL/Redo, MVCC, Lock, Transaction은 요청이 차례로 통과하는 계층이 아닙니다. MySQL에서는 이 기능의 큰 부분이 InnoDB 내부에 있고, PostgreSQL에서는 Buffer Manager·WAL·Lock·Transaction 등 여러 내부 모듈에 분산됩니다.
OS 경계: 저장 계층이 물리 장치를 항상 직접 제어하는 것은 아닙니다. 일반적으로 파일·블록 I/O는 운영체제와 파일시스템을 통합니다.

이제부터: 서버형 관계형 DBMS의 대표 요청 흐름위 레이어 지도에서 SQL 요청 하나가 내려갔다가 결과로 돌아오는 과정을 확대합니다.

처음 나온 용어 자세히 보기
  • Record/Row: 테이블의 한 기록. 여기서는 id=7 계좌입니다.
  • Index: 모든 기록을 읽지 않고 대상을 빨리 찾는 탐색 구조입니다.
  • Page: DBMS가 메모리와 파일 사이에서 데이터를 다루는 일정 크기의 블록입니다.
  • Buffer: Page를 메모리에 보관해 읽기와 변경에 사용하는 영역입니다.
  • Interface: 두 내부 구성요소가 서로 호출하는 약속입니다.
  • Library와 Engine: Engine은 저장을 맡는 역할, Library는 호출 가능한 코드라는 배포·결합 형태입니다. RocksDB처럼 라이브러리 형태의 저장 엔진도 있고, MySQL Storage Engine처럼 DBMS 내부 인터페이스에 결합되는 구현도 있으므로 두 단어는 동의어가 아닙니다.

이 단계의 범위 · 같은 UPDATE 예제를 사용하지만, 아래 제품 탭에 따라 실제 단계명·단계 수·내부 표현이 함께 바뀝니다. 저장 시스템 호출은 Executor/Execution이 수행 중 사용하는 경계이고, 완료 응답은 실행 뒤 프로토콜 계층이 전송하므로 별도의 SQL 처리 단계로 세지 않습니다.
