TRANSACTION / CONCURRENCY여러 Reader · 한 Writer

WAL mode에서는 Reader와 Writer가 함께 진행할 수 있지만 한 시점의 Writer는 하나입니다.

WAL RECOVERY / CHECKPOINTCommitted frame 유지 · DB 파일로 이전

Crash 뒤 첫 연결이 WAL 상태를 복구해 커밋된 frame을 다시 읽을 수 있게 합니다. Checkpoint는 해당 frame의 Page를 DB 파일로 옮깁니다.

ROLLBACK JOURNAL RECOVERYHot Journal의 이전 Page 복원

미완료 commit이 남긴 hot journal에서 원본 Page를 DB 파일에 되써서 트랜잭션 시작 전 상태로 되돌립니다.

잘 맞는 경우모바일·데스크톱·로컬 캐시처럼 서버 운영 없이 한 애플리케이션에 관계형 저장이 필요할 때.
비용과 주의점다중 Writer 확장이나 네트워크 파일시스템의 WAL 공유를 서버 DB처럼 기대하면 안 됩니다.
SQLite 복구 방식과 Checkpoint를 정확히 구분하기
  • WAL crash recovery: 비정상 종료 뒤 첫 연결이 WAL을 검사하고 wal-index를 복구합니다. 유효하게 커밋된 frame은 DB의 지속 상태이며 버리는 대상이 아닙니다.
  • Checkpoint: 커밋된 WAL Page를 원본 Database 파일로 옮기는 정상 유지 작업입니다. 활성 Reader의 end mark 때문에 중간에서 멈출 수 있습니다.
  • Rollback Journal recovery: hot journal에 보존된 변경 전 Page를 Database 파일에 되써서 미완료 트랜잭션을 취소합니다.

WAL mode는 같은 호스트 프로세스들이 wal-index용 shared memory를 사용할 수 있어야 합니다.

정체: 애플리케이션이 직접 호출하는 정렬 Key-Value 저장 라이브러리. SQL·Table·Join은 상위 계층의 책임

RocksDB · LSM-tree

LSM-tree(Log-Structured Merge-tree)는 새 쓰기를 먼저 메모리의 정렬 구조에 모으고, Flush로 변경 불가능한 정렬 파일(SST)을 만든 뒤 Compaction으로 파일 범위를 병합·재작성하는 저장 조직입니다. 아래는 RocksDB의 기본 Leveled Compaction을 이해하기 위한 대표 형태입니다.

모양 주의: 이름에 tree가 있지만 전체가 포인터로 이어진 하나의 노드 트리는 아닙니다. 메모리의 정렬 구조와 Level별 여러 SST 파일을 함께 관리합니다.

TRANSACTION / CONCURRENCYAtomic WriteBatch · Snapshot · 선택적 TransactionDB

WriteBatch는 여러 Key 변경을 한 번에 원자적으로 기록하고, DB Snapshot은 읽기가 볼 sequence 시점을 고정합니다. 충돌 검사와 BEGIN/COMMIT/ROLLBACK이 필요한 트랜잭션은 TransactionDB 계열을 선택해야 합니다.

RECOVERYWAL 사용 시 replay + MANIFEST

MANIFEST(현재 SST와 Level 구성을 기록한 메타데이터)로 구성을 복원하고 WAL에 남은 쓰기를 재생합니다. WAL을 끈 미flush 쓰기는 이 경로로 복구할 수 없습니다.

STORAGE SHAPEImmutable SST + Compaction

순차 쓰기에 유리하지만 amplification, 즉 한 요청 때문에 추가로 읽고·쓰고·보관하는 데이터 양과 Compaction stall을 조정해야 합니다.

잘 맞는 경우높은 쓰기 처리량, 큰 Key-Value 데이터, SSD와 workload에 맞춘 세밀한 조정이 필요할 때.
비용과 주의점SQL·스키마·관계형 제약은 제공하지 않으며 Compaction과 메모리·파일 수 튜닝 부담이 큽니다.
RocksDB에서 “트랜잭션 지원”의 정확한 의미
기본 DB API의 WriteBatch는 여러 변경을 원자적으로 기록하지만 일반적인 관계형 트랜잭션과 같다고 단정할 수 없습니다. RocksDB는 별도의 pessimistic TransactionDB와 OptimisticTransactionDB를 제공하며 충돌 탐지와 잠금 방식이 다릅니다. 상위 시스템이 RocksDB를 어떻게 감싸는지도 함께 확인해야 합니다.
